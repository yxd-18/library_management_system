**1.2.2 用户的特点 可直接替换稿**
本系统的最终用户主要分为三类：普通读者、图书管理员和系统管理员。不同用户在业务目标、操作频度和技术水平上存在差异，因此系统在需求分析和后续设计中需要体现角色差异化。

1. 普通读者  
普通读者主要使用系统完成图书查询、个人借阅记录查看、预约信息查看、续借申请及个人信息维护等操作。该类用户计算机操作能力差异较大，因此界面应尽量简洁直观，减少复杂输入，保证常见功能能够通过较少步骤完成。

2. 图书管理员  
图书管理员是系统最主要的高频使用者，承担图书录入、图书修改、借书、还书、预约处理、读者信息维护等核心业务操作。此类用户对业务流程较熟悉，但不一定具备较强的软件技术背景，因此系统应强调菜单层次清晰、提示信息明确、异常处理友好，并保证高频操作的效率。

3. 系统管理员  
系统管理员主要负责数据库初始化、运行环境配置、日志查看、备份记录管理和系统维护工作。该类用户使用频率相对较低，但对系统安全性、稳定性和可维护性要求更高。因此系统需要提供较明确的管理入口和操作反馈，以支持高风险操作的审慎执行。

综合来看，本系统既要满足业务高频处理的效率要求，也要保证新用户和非技术用户能够快速上手。因此，无论是控制台版本还是 Qt 前端版本，都应在交互设计上突出“功能清晰、反馈明确、操作可控”的特点。

**2.2 系统功能设计 可直接替换稿**
**2.2.1 功能模块设计**

根据需求分析结果，系统总体可划分为用户管理模块、图书管理模块、借阅管理模块、系统维护模块和前端展示模块五个部分。

1. 用户管理模块  
负责用户登录、角色识别、用户信息查询、读者信息维护及账户状态控制等功能，是系统权限控制和身份识别的基础模块。

2. 图书管理模块  
负责图书信息的新增、修改、删除、查询、分类关联、库存维护和图书状态展示，是系统管理馆藏资源的核心模块。

3. 借阅管理模块  
负责借书、还书、续借、预约、取消预约、挂失、逾期状态刷新以及借阅记录与预约记录查询等功能，是整个系统业务逻辑最集中的模块。

4. 系统维护模块  
负责备份记录管理、日志记录与查询、系统维护操作和运行数据追踪，用于提升系统的稳定性和可维护性。

5. 前端展示模块  
负责控制台界面和 Qt Widgets 图形界面的交互呈现，包括登录页面、管理员工作台、读者工作台以及主要数据展示入口。该模块在界面层与后端业务逻辑之间起到交互桥梁作用。

模块关系上，用户管理模块为其他模块提供身份基础；图书管理模块和借阅管理模块共享图书数据；系统维护模块为所有业务模块提供日志和维护支撑；前端展示模块通过仓储层或菜单服务层调用后端逻辑。

**2.2.2 借阅管理模块设计**

借阅管理模块是系统的核心业务模块，主要包括以下子功能：

1. 借书子模块  
在用户状态正常、借阅数量未超限、图书库存充足且无逾期限制的前提下，生成借阅记录并扣减图书可借库存。

2. 还书子模块  
根据借阅记录完成还书处理，更新借阅状态、记录归还时间，并回补图书库存。

3. 续借子模块  
在借阅记录未逾期、未挂失且续借次数未超上限时，允许延长借阅期限并更新续借次数。

4. 预约子模块  
当图书暂时无法借出时，允许用户生成预约记录，并按状态维护预约流程。

5. 取消预约子模块  
允许对“排队中”或“可取书”等有效预约状态进行取消，并同步更新相关业务状态。

6. 挂失子模块  
当图书发生遗失情形时，对借阅记录和图书状态进行相应处理，并保留业务追踪信息。

7. 记录查询子模块  
支持管理员和读者按条件查看借阅记录、逾期记录和预约记录。

**2.2.3 图书管理模块设计**

图书管理模块主要包括以下子功能：

1. 图书新增子模块  
录入图书 ISBN、书名、作者、出版社、分类、价格、库存和馆藏位置等信息，并完成合法性校验。

2. 图书修改子模块  
对已存在图书的信息进行更新，同时保证 ISBN 唯一性、库存数据合法性和分类关联正确性。

3. 图书删除子模块  
在图书不存在未归还借阅记录的情况下，允许删除对应图书数据。

4. 图书查询子模块

**2.5 接口及过程设计 可直接替换稿**
本系统接口设计主要体现在“界面层调用业务逻辑层，业务逻辑层再调用数据访问层”这一结构上。系统当前既包含控制台交互接口，也包含 Qt 图形界面接口，但两者在核心业务流程上均依赖统一的数据访问和业务处理逻辑。

1. 用户登录接口  
输入：用户名、密码。  
处理：查询用户信息、校验密码哈希、检查用户状态与角色。  
输出：登录结果、用户角色信息、错误提示信息。

2. 图书新增接口  
输入：图书基本信息，包括 ISBN、书名、作者、分类、价格、总库存、可借库存等。  
处理：校验必填项、校验库存合法性、检查 ISBN 是否重复、写入数据库。  
输出：新增成功或失败提示。

3. 借书接口  
输入：用户编号、图书编号、操作人编号。  
处理：检查用户状态、借阅上限、逾期情况、库存数量，生成借阅记录并更新图书库存。  
输出：借书成功或失败提示、借阅记录更新结果。

4. 还书接口  
输入：借阅记录编号、操作人编号。  
处理：校验借阅记录是否存在且未归还，更新归还状态并回补图书库存。  
输出：还书成功或失败提示。

5. 预约接口  
输入：用户编号、图书编号、操作人编号及备注信息。  
处理：检查用户状态、预约上限、是否重复预约、是否存在当前借阅，生成预约记录。  
输出：预约成功或失败提示。

6. 日志记录接口  
输入：操作人编号、操作类型、目标表、目标记录编号、操作内容。  
处理：写入系统日志表。  
输出：日志写入结果。

**2.6 界面设计 可直接替换稿**
本系统当前包含控制台界面和 Qt Widgets 图形界面两种交互形态。控制台界面主要用于后端业务验证和模块化菜单操作，Qt 图形界面主要用于系统展示、前端交互和课程设计演示。

1. 控制台界面设计  
控制台程序采用分级菜单方式组织功能，通常以登录入口为起点，根据用户角色分别进入管理员功能菜单或读者功能菜单。菜单项围绕用户管理、图书管理、借阅管理、系统维护等功能组织，强调输入提示清晰、异常输入可控和结果反馈明确。

2. Qt 登录界面设计  
Qt 前端首先提供统一登录入口，用户输入用户名和密码后进入系统。登录界面包含标题区、输入区、状态提示区和按钮区，能够根据登录结果给出明确反馈。

3. 管理员工作台设计  
管理员工作台主要展示用户数据、图书数据、借阅记录和预约记录等信息。界面通过多页或分区方式组织内容，并提供搜索、分页、详情查看及部分操作入口，以方便管理员进行集中管理。

4. 读者工作台设计  
读者工作台主要展示个人借阅记录、个人预约记录及图书目录信息。界面设计强调信息清晰、功能聚焦，使读者能够快速完成查询、续借、预约等常用操作。

5. 界面跳转关系  
系统界面总体遵循“登录页 -> 按角色进入工作台 -> 在各功能页之间切换 -> 执行操作并反馈结果”的流程。其中，管理员与读者在登录成功后进入不同的主功能界面，既共享统一的登录入口，又保持不同角色下的操作边界。

6. 界面设计原则  
本系统界面设计遵循以下原则：  
（1）功能分区明确，减少用户理解成本；  
（2）高频操作入口清晰，提高管理员工作效率；  
（3）错误提示和操作结果反馈及时，便于用户发现并纠正问题；  
（4）前端界面与后端业务逻辑解耦，便于后续扩展和维护。

用例1：输入正确数据库配置，预期结果为系统提示数据库连接成功，后续登录与查询功能可正常执行。
